# Changelog

## 3.2.0 (2026-11-13)
- **Automatic updates.** The installed app checks GitHub for a new version 15 seconds after it opens and every 4 hours, downloads it in the background and installs it when you close ORBIX, or at once with **Update to …, Restart** at the bottom of the sidebar. The download is checked against the SHA-512 in the release's `latest.yml` before it runs, the installer runs silently, and settings and conversations in `%LOCALAPPDATA%\ORBIX` are kept. Restarting while a session is working asks first. Settings → About → Updates shows where the update stands, has Check now and Release notes, and a switch to turn automatic updates off. Errors are explained in plain words (no connection, no update in the newest release, rate limit, damaged download, full disk), and a short log is kept in `%APPDATA%\ORBIX\update.log`. A copy run from source (`npm start`) never updates itself. Releases are published with `npm run release` (electron-builder, GitHub provider), which uploads the installer, its blockmap and `latest.yml`.
- **Sidebar.** Any conversation can be renamed, not only an open one: F2, a double-click or Rename in its menu; a renamed conversation keeps its place in the list. On a selected conversation, P pins or unpins it and Del asks to delete it. A long project opens the rest of its list in place with Show more (and Show fewer), remembered per project, instead of filling the filter box. Each project has a menu (⋯ or a right-click): new session, show the folder, copy its path, fold the other projects, unfold all, remove from the list. A project with an agent at work shows a live dot, and a conversation on its own git branch shows a branch mark. The sidebar drags out to 440 px, and a double-click on its edge (or the side panel's) resets the width.
- **Titles of long conversations.** The conversation list read titles only from the first 64 KB of each file, so a long conversation renamed (or titled) later kept its old name in the sidebar. The newest title now comes from the end of the file.
- **Broken syntax is caught at once.** After the agent writes or edits a JSON, `.js`, `.mjs` or `.cjs` file, ORBIX parses it (JavaScript is compiled, never run) and tells the agent the line that no longer parses, so it is fixed in the next step instead of surfacing later as a failed test. JSX, type annotations and JSON files that allow comments (`tsconfig.json`, `.vscode`) are left alone.
- **Light and depth.** A finish layer in `web/css/finish.css`: the workspace sheet is lit from the top in the accent colour, strongest on Home; the project's name in Home's question carries the accent; the task box is a raised slab whose border takes the accent on focus; Start and Send are lit from above and lift under the pointer; suggestions, project cards and session rows answer the pointer; dialogs blur the workspace behind them. Built from the theme tokens, so all themes and accents follow. Nothing moves on its own.
- **Search finds what you meant.** Ctrl+K and `@` file mentions no longer match letters scattered across a long title ("auth" in "Explain how this project is put together"); the letters of an abbreviation must sit close together, as in "pkg" for package.json.
- **Fit.** The top bar's Search box is centred in its row instead of touching the window's top edge. On the Connect a model list in a narrow window, the API key, Sign in and No key buttons keep their size at the right edge instead of stretching across the row.
- **The session view on Home's shapes.** One shape scale everywhere: sheets, cards, menus, dialogs, buttons and fields are rounder (9 to 18 px instead of 4 to 12). Tabs are pills without the underline; the status chip is a pill; Inspect and Focus are quiet buttons without outlines. The run panel shows its counts on small cards in the interface typeface, and its rows are spaced and rounded instead of ruled. Your message bubbles, code blocks and tooltips follow the same scale.
- **Always the current interface.** Each start of the app revalidates its files, so an update can never show styles or scripts from the version before. The conversation column widens to 920 px on large windows. Messages and the command palette say Providers, the name of the settings page, instead of AI providers; the error button reads Open Providers.
- **Sizes that fit the window.** The app scales its whole interface (Settings → Appearance → Interface size): Auto picks 115% on screens 2300 px wide or more and 125% from 3000 px, or choose 90% to 150%. Home's column, headline and task box grow with a wide window. The window reopens where it was closed, at the same size, maximized or not. The sidebar's logo row lines up with the top bar. The timeline strip no longer covers the session bar's Focus button. With the side panel at the window edge, its tabs show icons only (except the current one) instead of scrolling. A reopened session keeps the title you gave it instead of showing its first message.
- **The Windows app is ORBIX.** The browser version is gone: no `npx` install, no `npm run serve`, no npm package (`bin`, `files`) and no browser launcher (`src/main.mjs`). `npm start` now runs the app from source. The data folder rule for npm installs, the idle shutdown of the headless server, the `npm run doctor` console tool (Settings → Diagnostics does the same) and the CI packaging step went with it. The README, website, architecture notes and security notes now describe the Windows app and its installer.
- **ORBIX for Windows.** ORBIX now also runs as a Windows app, built with Electron 45: its own window, taskbar icon, Start menu and desktop shortcuts, and an installer (`npm run dist`) that installs per user without administrator rights. The page draws the top of the window, so the window buttons sit in the top row in the theme's colours and the empty parts of the top row move the window. Links open in your browser, right-click gives cut, copy, paste and spelling fixes, and a second launch brings the open window forward. The app and the browser version share `%LOCALAPPDATA%\ORBIX`. Starting the server is now one function (`src/app.mjs`) used by both.
- **A new Home.** One centred column: the planet, one question ("What should we work on in HUNT?"), a larger task box with a soft surface and a Build or Plan switch, and suggestions with icons. Below it, the sessions list drops its search box and filters until there are more than six sessions, keeps the times aligned at the edge (the pin takes the time's place on hover), and projects are cards. The folder path moved into the hover hint of the headline and the project button. The session's message box uses the same surface as the Home box.
- **One stylesheet for Home.** Home's styles came from four layers in three files, overriding each other. They now live in `web/css/home.css` alone; 351 old rules and selectors were removed, and `landing.css` is gone.
- **Sturdier agent.** Files outside the project folder now ask before the agent reads, searches or writes them (except under Allow everything), and helper agents do not reach outside it, so text in a project cannot send the agent after your keys elsewhere. Diffs show each change as its own hunk instead of marking everything between two edits as changed. A long run can compact more than once; when compaction summarizes your request, the request still reaches the model word for word. A reply cut off by the token limit no longer throws away the complete tool calls before the cut. A helper agent that runs out of context clears its old tool output and gives its answer instead of failing. An edit keeps the file's majority line ending. Regenerating or editing a message while files are being restored can no longer start a second run.
- **Contrast.** Every text colour now meets the WCAG 4.5:1 minimum on every surface in all four themes. In Light and Frost, the muted, success, warning and error colours were just under it on the sidebar. Hairlines are a step stronger, and text fields have a clearer edge.
- **Writing.** Provider descriptions are full phrases instead of fragments such as "Low prices." and "No key.", and the Providers page now mentions sign-ins.
- **About.** Settings → About says that ORBIX is in beta and developed by COM-X Corporation. It shows the COM-X mark drawn in characters, with a lime arc that travels around the ring, and links to the COM-X site and to GitHub for reporting a problem. With reduced motion turned on, the mark stays still.

The interface uses one size scale (11, 12, 13, 14, 15, 16, 20 and 28 px) instead of 16 sizes, and four weights instead of twelve. Headings on the website are set in Geist, and mono is kept for commands and code.
- **Steadier layout.** The session bar drops the words on Inspect and Focus in a narrow column instead of pushing them past the edge, and stops repeating the title in the message chip. Home's session list always shows the time on the right, with Open or Working beside the project. Home's suggestions stay centred on touch screens, where they are taller.
- **One card per provider.** Settings → Providers shows OpenAI once, with two ways in: your ChatGPT plan (sign in) or an API key. OpenCode is also one card, with Zen (sign in or key) and the Go plan. Each way keeps its own sign-in, key and status, so nothing already connected changes. Home's first-run list shows one OpenAI row, and Groq, Cerebras, Ollama and LM Studio now have descriptions that tell them apart.

- **Parallel agents on their own branches.** In a git project, the new-session box has a Separate branch choice. The session then works in its own folder, `.orbix/worktrees/<name>` (git worktree), on a new branch `orbix/<name>` cut from the commit you are on, so several sessions can work at once without touching each other or your project folder. The folder is kept out of `git status` through `.git/info/exclude`. The Running section of the sidebar lists each session with its branch, what it is doing (working, needs you, done) and for how long; two sessions can wait for your approval at the same time, and each shows that it needs you. The side panel's Review tab lists the files the branch changed against where it started, with their diffs, and offers Merge into the base branch (a merge commit; edits not committed yet are committed on the branch first), Keep branch and Discard (removes the folder and deletes the branch). Merge and Discard ask first. Merge refuses when your project folder has uncommitted changes or is on another branch; on a conflict it is aborted and both stay as they were, and the panel lists the files. A branch session closed before it saved or changed anything leaves no branch behind. Git runs with the same guards as the Changes panel (no repository hooks, filters or signing programs).
- **Diffs show what changed.** In an edit, a proposed edit and the Changes and Review panels, the words that changed within a line are marked, and every line has the syntax colour of its file type. A rewritten line is shown whole; very large diffs stay plain so they open fast.
- **One error state, with Retry.** A failed reply, a session that ended, the file tree, a file, the Changes and Review panels and their diffs, the folder picker, the model list, Ctrl+K file search and every Settings page that loads now show the same box: what failed, why, a hint when there is one, and Retry (or Reopen session for a session that ended). Ctrl+K no longer reports a failed file search as "No matches".

If it fails, the agent gets the output and fixes the cause, and the check runs again (at most three times per run). It runs through the same shell, hooks and approvals as any command, and is not repeated when the agent already ran it after its last edit. Then the fast model (or the session's model) reads the run's diff once and reports real defects; if it finds any, the agent gets one more round to fix them. Changes under 5 lines are not reviewed. ## 3.0.0
- **ORBIX - Unified ADE**: a native Windows app where an AI agent works on your project. It reads files, edits them and runs commands, and asks before it changes anything. Every file change can be undone.
- **Its own agent**: 17 providers (Anthropic, OpenAI, Google Gemini, xAI, Groq, Mistral, DeepSeek, OpenRouter, Together, Fireworks, Cerebras, Moonshot, Z.ai, Qwen, Ollama, LM Studio, any OpenAI-compatible server), Sign in with OpenRouter, live model lists, prices and context sizes, thinking levels, automatic retries, cost and context display.
- **Agent tools**: read, write, edit, bash (PowerShell on Windows), glob, grep, web fetch, helper agents, task list, MCP servers, skills, custom slash commands, `@file` mentions, images and text attachments, `/compact`, `/plan`, `/model`, `/cost`, `/undo`, retry and HTML export.
- **Model roles**: choose a fast model (chat titles, summaries, helper agents) and a plan model (`/plan`) in Settings → AI providers → Models, or per session with `/model fast|plan <model>`. Titles never use the main model.
- **Hooks**: your own commands before and after tool calls, on each message and when the agent stops (`data/hooks.json`, or `.orbix/hooks.json` in a project, which asks once before it runs). Exit code 2 blocks the action and tells the agent why. Listed in Settings → Tools & MCP and with `/hooks`.
- **Branching**: branch a conversation from any message of yours (or `/branch`). It opens in a new tab with everything before that message; your files are not changed.
- **Web search**: the `web_search` tool, off until you add Brave Search, Tavily or your own SearXNG in Settings → Tools & MCP. Needs no approval once on; the key is stored encrypted.
- **Project memory and goals**: `/init` writes or refreshes AGENTS.md, `/memory` shows where it is, and `/goal <text>` keeps the agent working by itself (up to 6 rounds, Esc stops it) until it ends with GOAL_DONE.
- **Interface**: animated home, inline approvals above the message box (1 allow once, 2 allow for the session, Esc deny), `/` and `@` pop-ups, coloured command output, diffs, tabs, side panels (files, git, plan, agents, console), command palette (Ctrl+K), light and dark themes, measured status bar.
- **Nothing to install**: the release zip includes its own Node.js (checksum verified).
- **Safe by default**: local server on `127.0.0.1` with a per-launch token, strict Content-Security-Policy, keys encrypted with Windows DPAPI, private-network protection in web fetch, MCP project servers need your approval.
- **Optional**: if the OMP CLI is installed, sessions can also run with it.
