# Changelog

## 3.8.0 (2026-11-20)
- **Chat first, as in Antigravity.** The side panel starts closed and opens when you ask for it (toolbar, Ctrl+J or the Overview card); the sidebar is narrower (240px; a width you dragged is kept); the conversation is a narrower, centred column. Existing setups switch to this once, on the first start of 3.8.
- **Sharper replies.** Tighter line spacing and list rhythm, white bullets, calmer headings, inline code in amber on a faint ground with no border (file paths look the same and underline when you point at them), and a compact bubble for your messages.
- **👍 and 👎 on every reply**, in one quiet row with copy, retry, the time and the model. Your mark stays on this PC; 👎 offers to answer again, switch the model, or report the problem (Settings → Give feedback, with the model filled in).
- **Home** asks its question at a calmer size.
- **Cleanup.** Removed the styles of the old Settings overview page and four exports nothing used.

## 3.7.0 (2026-11-20)
- **Settings, redesigned as in Antigravity.** A card over the workspace with the page list on the left: General, Application, Appearance, Shortcuts, Notifications, Providers, Models and Browser; Customizations (Instructions, Checks, Tools & MCP); a page for each project; Conversations and Worktrees; Give feedback and this copy of ORBIX at the bottom. Pill buttons, pill selects and quiet cards; × or Esc closes it. Ctrl+K finds any setting by name and opens its page.
- **General.** Permission preset, Tool permissions (trusted commands, where commands run), Network access rules, what Enter does while the agent works (Steer or Queue; Alt+Enter does the other), the send key and following output.
- **Network access rules.** Sites the agent may read with `web_fetch` without asking, and sites it may never read, also after a redirect. With an allowed list, every other site asks first, in every preset; helper agents read only listed sites.
- **Shortcuts you can change.** Settings → Shortcuts lists every action with its keys: + records new keys, the bin removes them, Reset puts them back; a key taken from another action says so. New: Ctrl+P (find a file), Ctrl+U (Automations), Ctrl+[ and Ctrl+] (back and forward), Ctrl+Shift+. and Ctrl+Shift+, (side panel tabs), Ctrl+/ (shortcuts). Menus show your keys.
- **Built-in browser in the Windows app.** The Browser tab is now a real browser view with its own session: any site, back, forward, reload, address suggestions from your history. Settings → Browser: open links from replies in it, the download folder, clear browsing history, clear its cookies and site data. Its pages get no access to ORBIX and no camera, microphone or location.
- **Project pages.** Each project in Settings shows its folder, recent conversations, the AGENTS.md and `.agents/rules` files the agent reads (with their triggers), and its check command.
- **Notifications.** A volume slider for the chime.
- **Give feedback.** Bug report, feature request, model problem or general feedback, with optional version facts, opened as a GitHub issue you check before sending. Nothing is sent from ORBIX.
- **Removed.** The Overview page of Settings, its search box (Ctrl+K does it now) and the separate shortcuts dialog.

## 3.6.0 (2026-11-20)
- **Automations** (sidebar → Automations). A prompt that ORBIX starts by itself every hour, every day, on weekdays or every week, in a project, as a new conversation. Run now, turn on or off, edit, delete; the list shows the next and last run and whether one is working. They run while ORBIX is open: a time missed while it was closed is skipped, and a run still working is not started twice. Each run is an ordinary conversation, so in Ask first it waits for your OK in Review.
- **Browser** (side panel). Lists the web apps running on this computer (the usual dev-server ports, with their page titles) and previews one in a sandboxed frame next to the conversation, with reload and "open in your browser". Type a port, a localhost address, a site or a search: other sites and searches open in your own browser. ORBIX allows frames only from localhost.
- **Side question** (side panel, or `/btw <question>` in the message box). Ask about the conversation while the agent keeps working: what it changed, why, where something is. The answer comes from the conversation so far, with no tools, and is not added to it.
- **Rule files with triggers.** Markdown files in the project's `.agents/rules` folder, as in Antigravity. Front matter `trigger: always_on` (the default) puts a rule in every prompt; `model_decision` (with a `description`) and `glob` (with `globs`) list it for the agent to read when it applies; `manual` only when you @mention it.
- **Fixes.** The toolbar lost the page name (Runs, Review, Automations) in windows narrower than 900px; side-question text was set in the code font.
- **Cleanup.** Five merged feature branches and a stale worktree rule in `.gitignore` removed; the website's release list keeps the main releases and links to the rest.

## 3.3.0 (2026-11-20)
- **Runs.** A run takes one task from its description to changes you have reviewed. Start one from Runs (Ctrl+2): pick the project, describe the task, and choose Plan first or Straight to work.
  - Every run works in its own git worktree and branch, so your checkout is untouched until you apply, and several runs can work at once.
  - Plan first: the agent only reads, then saves an implementation plan. You can comment on a passage, send feedback and get a new revision; every revision stays readable.
  - Approving the plan shows exactly what it allows: the worktree, the branch, and either file edits or file edits and commands. Files outside the worktree and destructive commands (recursive delete, push, publish, history rewrite, system changes) ask every time, whatever you approved.
  - The run page has a timeline where each step opens what it produced, plus the plan, the changes, the test log and the walkthrough.
  - Apply merges into the branch the run started from. Your uncommitted work in other files is kept; if a file you edited would be overwritten, or the merge conflicts, nothing is changed on either side. Discard removes the worktree and branch.
- **Review** (Ctrl+3). One queue across all projects for everything that waits for you: approvals, plans, finished changes, questions, interrupted and failed runs.
- **Recovery.** Everything a run does is written to an append-only log. A run that was working when ORBIX closed is marked Interrupted and names what was still in flight. It continues only after you say so, and the agent is told to check the state first; ORBIX does not repeat the action.
- **Calmer conversations.** When a reply is done, its steps fold into one line above the answer: "Worked for 14s", with what was read, searched, run and changed, and whether the tests passed. Click it to see every step. A failed check stays in view. While the agent works, the line at the bottom says what it is waiting on and for how long.
- **Quieter interface.** A narrower reading column, flatter buttons and message box, icon-only message actions (the words are in the tooltips), and one summary of a turn instead of two. Buttons that start slow actions show a spinner and cannot be pressed twice.
- **Cleanup.** Removed unused code, styles and settings left from older versions, merged duplicated helpers, and corrected the docs (README, CONTRIBUTING, SECURITY, ARCHITECTURE).
- **Clearer git errors.** When git has no name and email set, Apply says so and shows the two commands that fix it.
- **Tests.** `npm run e2e` drives the real interface through a whole run against a scripted model. `docs/parity.md` tracks the feature matrix against the Antigravity App and what is verified.

## 3.2.2 (2026-11-15)
- **Accurate model facts and thinking levels.**
  - ChatGPT-plan models show their real context window (272K, not 1.1M), so the context meter is right and long conversations are summarized before they hit the limit. They show no per-token cost, because plan usage is not billed per token.
  - Each model offers the thinking levels its provider actually accepts, including the new Max level. ORBIX asks the API once a week which levels a model takes (a refused request, which costs nothing) and keeps the answer, so a level the model list advertises but the API refuses (such as Ultra) is never offered. If a level is refused anyway, the turn runs again at the nearest accepted one instead of failing.
  - Thinking off is offered only on models that can stop thinking, and is sent as a real "off". Before, choosing Off on a model that always thinks silently used its default level. A new conversation starts at the model's own default level (the ChatGPT plan's default for each model).
  - The thinking menu names levels plainly (Extra high, Max) and says when a model always thinks. In the model picker, "thinking" is only shown where a provider mixes thinking and non-thinking models, and hovering a model shows its id, context window and levels.
- **Engine structure.** The agent's 1,600-line core is split into files by job (model and thinking, tool calls and approvals, end-of-run checks, usage and cost) and joined into one class, with a test that every part is present exactly once. Behaviour is unchanged.
- **Repository.** Retook every README and website screenshot from the current app, removed outdated screenshots and an obsolete design note, corrected the contributor guide (CI, releasing, file layout) and the architecture document, and the tests no longer leave temporary folders behind.
- **Model providers and lists.** Every provider was checked live against its real API.
  - A wrong key now reads "The provider refused the API key" for Google Gemini and xAI too (they answer with a 400), and Mistral, Cerebras and vLLM-style errors show their message instead of raw JSON.
  - Model lists offer chat models only: Gemini's music (Lyria), live-audio, Deep Research, computer-use, speech and image models are no longer listed, also when the list comes from the model catalog, which is now sorted like the others.
  - Loading a model list has a 20-second limit, so a provider that hangs is reported ("did not answer within 20 seconds") instead of freezing the model picker or Check & save.
  - Ollama and LM Studio that are not running say so ("Ollama is not answering at http://localhost:11434/v1. Start Ollama and try again."), and a custom server without a model list says where it looked and that the address usually ends in /v1.
  - Lists are reused for a minute, so the model picker opens at once, and are loaded again as soon as you add, remove or change a provider. An open session now sees those changes too (before, it kept the list it started with), and retries a provider that failed after a minute.
- **Scene themes.** Five new themes in Settings → Appearance → Scenes, each with its own colours and a moving picture behind the conversation: ORBIX (a planet with a lime signal running round its ring), Synthwave (a neon grid running to a striped sun), Koi pond (light, with pixel koi and lily pads), Aurora (northern lights over a pine ridge) and Halftone dusk (a warm dot-screen sun). A soft veil keeps the reading column calm, the scene moves faster while the agent works, and fireworks go up at the sides when a task finishes. Animate scenes turns the motion off; scenes are also still when Windows is set to reduce motion, and they slow down when the window is in the background. Fireworks fly over the whole window, so Settings → Appearance → Preview the finish shows them above the dialog, in any theme. In a narrow window the scene recedes behind a stronger veil, the tab row always sits on the plain sheet colour, and lily pads keep to the open water beside the text.
- **A new sidebar.** Rebuilt along the lines of the best agent apps: the ORBIX mark on its own (no tile) beside the wordmark, on the same line as the tabs; an outlined New session button; Home and Search; then Projects, with a filter button and an Open folder button on its header (the filter box only appears when you open it, and Esc closes it). Conversation titles line up under the project name with no tree lines, the current one is a softly outlined pill, and each open conversation shows its status as a dot under the folder icon: working, waiting for your OK (amber), finished while you were away (the accent, with the title in bold until you open it), or open. Settings has its own row at the bottom, with the model connection beside it. Everything shares one inset, so every edge lines up, in every theme and in the collapsed rail. The session bar's "current question" link is plain text instead of a pill.
- **Frame.** The window layout is a single column (workspace, then status bar), so the status bar can no longer be pushed below the window at any interface size.
- **Home with no sessions.** It says "No sessions yet" and how to start one, instead of "No matching sessions" with a Reset filters link when nothing was filtered. A filter or search with no results offers Show all sessions.
- **Calm interface.** The "light and depth" layer is replaced by a flat one. Dark is a neutral graphite, with the workspace darker than the frame around it; no glows, gradients or lit edges. Replies carry no name plate (the model shows at the end of the reply's actions), and your messages need no "You" label. Tool steps are single quiet lines without icon tiles or the rail; their duration and tick appear under the pointer, and only steps that wait or fail keep a colour. A failed reply is a line of red text with a thin rule instead of a red box. Tabs read as plain titles, the session bar shows its counts on hover, the timeline is grey until the pointer reaches it, and primary buttons are plain ink. Home's question is plain text with the project name in the accent.
- **About.** Settings → About shows the update status next to the version, Copy version info for bug reports, the Electron, Chromium and Node.js versions, the Windows version (named by its build, so Windows 11 is not reported as 10), where commands run and the data folder with an Open button, plus Help, links and the license. The Settings window no longer cuts off the bottom of long pages.

## 3.2.0 (2026-11-13)
- **Automatic updates.** The installed app checks GitHub for a new version 15 seconds after it opens and every 4 hours, downloads it in the background and installs it when you close ORBIX, or at once with **Update to …, Restart** at the bottom of the sidebar. The download is checked against the SHA-512 in the release's `latest.yml` before it runs, the installer runs silently, and settings and conversations in `%LOCALAPPDATA%\ORBIX` are kept. Restarting while a session is working asks first. Settings → About → Updates shows where the update stands, has Check now and Release notes, and a switch to turn automatic updates off. Errors are explained in plain words (no connection, no update in the newest release, rate limit, damaged download, full disk), and a short log is kept in `%APPDATA%\ORBIX\update.log`. A copy run from source (`npm start`) never updates itself. Releases are published with `npm run release` (electron-builder, GitHub provider), which uploads the installer, its blockmap and `latest.yml`.
- **Sidebar.** Any conversation can be renamed, not only an open one: F2, a double-click or Rename in its menu; a renamed conversation keeps its place in the list. On a selected conversation, P pins or unpins it and Del asks to delete it. A long project opens the rest of its list in place with Show more (and Show fewer), remembered per project, instead of filling the filter box. Each project has a menu (⋯ or a right-click): new session, show the folder, copy its path, fold the other projects, unfold all, remove from the list. A project with an agent at work shows a live dot, and a conversation on its own git branch shows a branch mark. The sidebar drags out to 440 px, and a double-click on its edge (or the side panel's) resets the width.
- **Titles of long conversations.** The conversation list read titles only from the first 64 KB of each file, so a long conversation renamed (or titled) later kept its old name in the sidebar. The newest title now comes from the end of the file.
- **Broken syntax is caught at once.** After the agent writes or edits a JSON, `.js`, `.mjs` or `.cjs` file, ORBIX parses it (JavaScript is compiled, never run) and tells the agent the line that no longer parses, so it is fixed in the next step instead of surfacing later as a failed test. JSX, type annotations and JSON files that allow comments (`tsconfig.json`, `.vscode`) are left alone.
- **Light and depth.** A finish layer in `web/css/finish.css`: the workspace sheet is lit from the top in the accent colour, strongest on Home; the project's name in Home's question carries the accent; the task box is a raised slab whose border takes the accent on focus; Start and Send are lit from above and lift under the pointer; suggestions, project cards and session rows answer the pointer; dialogs blur the workspace behind them. Built from the theme tokens, so all themes and accents follow. Nothing moves on its own.
- **Search finds what you meant.** Ctrl+K and `@` file mentions no longer match letters scattered across a long title ("auth" in "Explain how this project is put together"); the letters of an abbreviation must sit close together, as in "pkg" for package.json.
- **Fit.** The top bar's Search box is centred in its row instead of touching the window's top edge. On the Connect a model list in a narrow window, the API key, Sign in and No key buttons keep their size at the right edge instead of stretching across the row.
- **The session view on Home's shapes.** One shape scale everywhere: sheets, cards, menus, dialogs, buttons and fields are rounder (9 to 18 px instead of 4 to 12). Tabs are pills without the underline; the status chip is a pill; Inspect and Focus are quiet buttons without outlines. The run panel shows its counts on small cards in the interface typeface, and its rows are spaced and rounded instead of ruled. Your message bubbles, code blocks and tooltips follow the same scale.
- **Always the current interface.** Each start of the app revalidates its files, so an update can never show styles or scripts from the version before. The conversation column widens to 920 px on large windows. Messages and the command palette say Providers, the name of the settings page, instead of AI providers; the error button reads Open Providers.
- **Sizes that fit the window.** The app scales its whole interface (Settings → Appearance → Interface size): Auto picks 115% on screens 2300 px wide or more and 125% from 3000 px, or choose 90% to 150%. Home's column, headline and task box grow with a wide window. The window reopens where it was closed, at the same size, maximized or not. The sidebar's logo row lines up with the top bar. The timeline strip no longer covers the session bar's Focus button. With the side panel at the window edge, its tabs show icons only (except the current one) instead of scrolling. A reopened session keeps the title you gave it instead of showing its first message.
- **The Windows app is ORBIX.** The browser version is gone: no `npx` install, no `npm run serve`, no npm package (`bin`, `files`) and no browser launcher (`src/main.mjs`). `npm start` now runs the app from source. The data folder rule for npm installs, the idle shutdown of the headless server, the `npm run doctor` console tool (Settings → Diagnostics does the same) and the CI packaging step went with it. The README, website, architecture notes and security notes now describe the Windows app and its installer.
- **ORBIX for Windows.** ORBIX now also runs as a Windows app, built with Electron 45: its own window, taskbar icon, Start menu and desktop shortcuts, and an installer (`npm run dist`) that installs per user without administrator rights. The page draws the top of the window, so the window buttons sit in the top row in the theme's colours and the empty parts of the top row move the window. Links open in your browser, right-click gives cut, copy, paste and spelling fixes, and a second launch brings the open window forward. The app and the browser version share `%LOCALAPPDATA%\ORBIX`. Starting the server is now one function (`src/app.mjs`) used by both.
- **A new Home.** One centred column: the planet, one question ("What should we work on in HUNT?"), a larger task box with a soft surface and a Build or Plan switch, and suggestions with icons. Below it, the sessions list drops its search box and filters until there are more than six sessions, keeps the times aligned at the edge (the pin takes the time's place on hover), and projects are cards. ## 3.0.0
- **ORBIX - Unified ADE**: a native Windows app where an AI agent works on your project. It reads files, edits them and runs commands, and asks before it changes anything. Every file change can be undone.
- **Its own agent**: 17 providers (Anthropic, OpenAI, Google Gemini, xAI, Groq, Mistral, DeepSeek, OpenRouter, Together, Fireworks, Cerebras, Moonshot, Z.ai, Qwen, Ollama, LM Studio, any OpenAI-compatible server), Sign in with OpenRouter, live model lists, prices and context sizes, thinking levels, automatic retries, cost and context display.
- **Agent tools**: read, write, edit, bash (PowerShell on Windows), glob, grep, web fetch, helper agents, task list, MCP servers, skills, custom slash commands, `@file` mentions, images and text attachments, `/compact`, `/plan`, `/model`, `/cost`, `/undo`, retry and HTML export.
- **Model roles**: choose a fast model (chat titles, summaries, helper agents) and a plan model (`/plan`) in Settings → AI providers → Models, or per session with `/model fast|plan <model>`. Titles never use the main model.
- **Hooks**: your own commands before and after tool calls, on each message and when the agent stops (`data/hooks.json`, or `.orbix/hooks.json` in a project, which asks once before it runs). Exit code 2 blocks the action and tells the agent why. Listed in Settings → Tools & MCP and with `/hooks`.
- **Branching**: branch a conversation from any message of yours (or `/branch`). It opens in a new tab with everything before that message; your files are not changed.
- **Web search**: the `web_search` tool, off until you add Brave Search, Tavily or your own SearXNG in Settings → Tools & MCP. Needs no approval once on; the key is stored encrypted.
- **Project memory and goals**: `/init` writes or refreshes AGENTS.md, `/memory` shows where it is, and `/goal <text>` keeps the agent working by itself (up to 6 rounds, Esc stops it) until it ends with GOAL_DONE.
- **Interface**: animated home, inline approvals above the message box (1 allow once, 2 allow for the session, Esc deny), `/` and `@` pop-ups, coloured command output, diffs, tabs, side panels (files, git, plan, agents, console), command palette (Ctrl+K), light and dark themes, measured status bar.
- **Nothing to install**: the release zip includes its own Node.js (checksum verified).
- **Safe by default**: local server on `127.0.0.1` with a per-launch token, strict Content-Security-Policy, keys encrypted with Windows DPAPI, private-network protection in web fetch, MCP project servers need your approval.
- **Optional**: if the OMP CLI is installed, sessions can also run with it.
